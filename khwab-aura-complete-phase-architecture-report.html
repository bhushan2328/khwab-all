Architecture rule: khwab-core must remain Android-free. The app communicates with core only through khwab-integration. Aura is an Android library consumed by the app.

The Gradle settings file in khwab/ wires all modules together:

include(":integration")  // khwab-integration/integration

2. Engine Pipeline

AuraConfig  (latitude, longitude, autoTime, autoWeather, stormIntensity, ...)
    │
    ▼
AuraEngine.generateTheme(config)
    ├── TimeState.now()                 (real device clock)
    ├── SolarCalculator.calculate()     (GPS → sunriseHour, sunsetHour)
    ├── TimePhaseEngine.calculate()     (time + solar → TimePhase enum)
    ├── MoonPhaseCalculator.calculate() (Julian date → MoonStyle)
    ├── SeasonEngine.calculate()        (latitude + month → Season)
    ├── WeatherEngine.refresh()         (live weather → WeatherState)
    ├── LightingEngine.update()         (time + weather → LightingState)
    └── ThemeEngine.createTheme()       (all above → AuraTheme)
                                                │
                                                ▼
                                           AuraTheme
                                         (consumed by Compose UI)

AuraTheme is the single contract between engine and UI. It carries:

  • timePhase: TimePhase — categorical phase for non-sky systems
  • weatherState: WeatherState — current weather
  • profile: ThemeProfile — derived visual styles (sun, moon, clouds, animation…)
  • sunriseHour: Float?, sunsetHour: Float? — GPS solar times (null if no location)
  • isSolarAccurate: Boolean — true when GPS solar data is in use
  • lighting: LightingState — authoritative intensity/ambient from LightingEngine
  • animationsEnabled: Boolean — global animation gate

4. Engine Layer

SolarCalculator

Pure math, no network. Implements the standard sunrise equation using Julian dates.

  • Input: latitude, longitude, date
  • Output: SunTimes(sunriseHour: Float, sunsetHour: Float) in decimal hours, or null for polar regions
  • Used by AuraEngine to populate AuraTheme.sunriseHour/sunsetHour

TimePhaseEngine

Converts time to a TimePhase enum. Two modes:

  • Fixed schedule (no GPS): midnight 0–4h, pre-dawn 4–5:30h, sunrise 5:30–6:30h, morning 6:30–11:30h, noon 11:30–13:30h, afternoon 13:30–17:30h, sunset 17:30–18:30h, evening 18:30–21h, night 21–24h
  • Solar schedule (GPS available): phases derived from minutes-since-sunrise with ±20 min twilight bands around sunrise/sunset

LightingEngine

Continuous sine-curve intensity model:

phaseOffset = (13/24) × 2π − π/2       // peak at 13:00
raw = sin((h/24) × 2π − phaseOffset)  // −1..1
baseIntensity = (raw+1)/2 × 0.85 + 0.15  // 0.15..1.0
clampedBase = min(0.30, base) if h < 5 or h ≥ 21  // night floor
intensity = clampedBase × weatherMultiplier

Weather multipliers: CLEAR 1.0 · CLOUDY 0.80 · RAIN 0.65 · FOG 0.60 · SNOW 0.90 · STORM 0.45

SunEngine

Solar arc positioning. Returns normalised SunPosition(x, y, angle):

t = (fractionalHour − sunriseHour) / dayLength   [0,1]
arcAngle = π(1 − t)
x = 1 − t
y = 0.82 − sin(arcAngle) × 0.77   // 0.82 horizon → 0.05 zenith at noon

MoonPhaseCalculator

Julian-date synodic cycle. Synodic month = 29.5306 days. Reference new moon: 2000-01-06 18:14 UTC.

phaseFraction() returns 0.0 (new moon) → 0.5 (full moon) → 1.0 (new moon again).

Illuminated fraction used across StarLayer, MoonLayer, SkyLayer: k = (1 − cos(2π·phase)) / 2

SeasonEngine

Calendar-month lookup with hemisphere flip. Northern: Winter=Dec-Feb, Spring=Mar-May, Summer=Jun-Aug, Autumn=Sep-Nov. Southern: opposite.

6. Phase Color — Atmospheric Color System

Phase Color replaced the original hard-coded per-phase palette system and artificial LightLayer color filters with a physically inspired multi-layer atmospheric model.

Core principle

The sky color is treated as the result of several orthogonal contributions composited in order:

BASE TIME-OF-DAY ATMOSPHERE      (SkyLayer — primary source)
  + WEATHER MODULATION OVERLAY   (SkyLayer — semi-transparent veil)
  + SUBTLE SCENE HINT            (LightLayer — ≤6% alpha trace only)

LightLayer — Phase Color changes

The original system applied destructive global color filters: 27% indigo at MOONLIGHT, 33% blue at PRE_DAWN, 40% black at NIGHT, 20% orange at SUNSET. These were replaced:

SUNSET20%6%0x10E88040 (trace warm orange)

MOONLIGHT27%0%transparent

Max darkening from LightingEngine: reduced 40% → 22%. Night sky darkness now comes from SkyLayer gradients, not a black overlay.

Weather overlay principles

The weather overlay is a second semi-transparent gradient on top of the sky. Key rules:

  • RAIN + SUNSET must still look like a rainy sunset — warm horizon survives at 16% suppression vs 24% for midday
  • STORM + SUNSET: warm horizon bleeds through at 22% vs 33% for midday
  • FOG at sunrise/sunset uses warm fog hue #D0C4B0; other times uses cool #BCC8D0
  • CLEAR → no overlay drawn at all

7. Phase 11 — Continuous Atmospheric Color Physics

Phase 11 replaced the final remaining discrete TimePhase → palette lookup in SkyLayer with a continuously computed solar-elevation-driven atmospheric model. This is the current production implementation.

Solar elevation normalisation

Function solarElevationNorm(currentHour, sunriseHour, sunsetHour) returns solarElev ∈ [-1, +1]:

+1.0  =  solar noon         (sun at maximum height)
 0.0  =  horizon crossing   (exact sunrise or sunset)
-1.0  =  solar midnight     (sun at minimum — deepest night)

GPS-accurate path (when sunriseHour/sunsetHour available from AuraTheme):

tDay = (currentHour − sunriseHour) / dayLength          [0..1]
solarElev = sin(π × tDay)                               [0..+1] daytime

tNight = (currentHour − sunsetHour) / nightLength       [0..1]
solarElev = −sin(π × tNight)                            [0..-1] nighttime

Mathematically identical to SunEngine.calculateSolarArc() — no calculation is duplicated. Polled every 30 seconds via LaunchedEffect, matching SunLayer's cadence.

Fallback (no GPS): same formula with fixed rise=06:00, set=20:00.

Seven atmospheric anchor palettes

Each palette has 5 stops: zenith / upper sky / mid sky / lower atmosphere / horizon.

Interpolation with nonlinear horizon response

This is the key physical innovation. In the twilight bands, the five stops use different blend curves:

tHorizon = tLinear ^ 0.5   // horizon reaches warm target FASTER (√ curve)
tMid     = tLinear         // mid sky follows linearly
tUpper   = tLinear ^ 1.6   // zenith/upper sky LAGS behind (power curve)

Result: at exact sunrise, the zenith is still cool blue-violet while the horizon is already warm golden. The warm region grows upward as the sun rises, and shrinks back down as it sets — continuous, not a palette switch.

Moonlight atmospheric contribution

Applied after base palette computation. Active only when solarElev < −0.05.

illumination  = (1 − cos(2π·phase)) / 2       // 0=new, 1=full
nightDepth    = (−solarElev − 0.05) / 0.95    // how deep into night
maxLift       = 0.05 × illumination × nightDepth

Per-stop lift ratios: [0.15, 0.30, 0.55, 0.80, 1.00]  (zenith → horizon)
Colour cast:          R×0.75, G×0.80, B×1.00           (cool-silver, not blue)

8. Rendering Layer Reference

SkyLayer — Phase 11 (current)

  • Primary color source for entire scene
  • 5-stop vertical gradient: zenith / upper / mid / lower / horizon
  • Solar elevation polled every 30 s; animateColorAsState(tween(3000)) on all 9 stops
  • Two Canvas passes: base atmosphere + weather overlay
  • Zero per-frame allocations

SunLayer

  • Four-layer atmospheric solar rendering: wide haze → mid scatter bloom → local corona → solar disc
  • Disc radius: size.minDimension × 0.048
  • Low-angle horizontal stretch (DAWN/SUNSET) for horizon scatter simulation
  • Solar position: GPS arc (SunEngine) or circle fallback; polled every 30 s
  • No rotating ray spokes — replaced with radial gradient bloom layers

MoonLayer

  • Continuous terminator from MoonPhaseCalculator.phaseFraction()
  • Shadow = union of half-disc + elliptical cap (correct waxing/waning distinction)
  • Deterministic lunar surface texture (8 mare/highland features, fixed seed)
  • Phase-dependent halo/glow; weather visibility multipliers
  • Position: phase-offset from sun arc (~phase×24h offset)
  • Disc radius: size.minDimension × 0.055

CloudLayer

  • Six morphologies: CUMULUS, WISPY, LAYERED, FRACTURED, TOWER, SMALL
  • Three depth planes (far/mid/near); clouds per style: STORM=(5,4,3), OVERCAST=(4,3,2), BROKEN=(3,2,2), SCATTERED=(2,2,1), FEW=(1,1,1)
  • Pre-baked unit-scale paths (CachedMassPaths) — zero per-frame Path allocation
  • Sub-masses: primary envelope + 1–4 internal lobes + optional shadow pocket + 0–2 edge wisps
  • Atmospheric perspective: far clouds blend toward neutral grey (atmBlend = depth×0.48)
  • Horizon integration fade prevents hard visible edges
  • Wind modulation: wispy 1.4×, tower 0.7×, by depth plane

StarLayer

  • 120 stars: 78 faint / 28 medium / 10 bright / 4 very bright (realistic magnitude distribution)
  • Four stellar color temperatures: blue-white 15%, neutral 60%, warm-white 20%, subtle-warm 5%
  • Twinkle: restrained sine-wave alpha modulation per star (±2–10%)
  • Moonlight suppression: faint stars suppressed more strongly than bright
  • Horizon atmospheric extinction + fog fade-start at y=0.38 (vs 0.55 clear)
  • Halos only on Tier 2/3 stars (brightest 14)

WeatherLayer

Rain

  • 110–165 drops in 3 depth planes (55% back / 35% mid / 10% front)
  • Per-drop atmospheric tint inherited from sky phase (near-neutral, never blue)
  • Streak length varies by depth and speed; horizon fade by depth plane
  • Wind angle affects streak direction; per-drop angle jitter

Snow

  • 90 flakes; 4 visual types: tiny point (type 0), 3-arm wispy crystal (type 1), soft diffuse circle (type 2), foreground speck (type 3)
  • Sinusoidal lateral sway per flake (realistic pendulum drift)

Fog

  • 10 layers; each layer has 2 overlapping ovals drifting independently
  • Sinusoidal vertical ripple prevents static band appearance
  • Fog color inherits from sky phase (not always white-grey)

Lightning

  • LightningBus drives event timing
  • 3 categories: distant (50%), medium (30%), close (20%)
  • 1–3 pulses per event with realistic brightness dropoff
  • Full-screen tint capped at 20%; atmospheric bloom in 3 concentric rings

SeasonLayer

BirdLayer

  • Active: MORNING/NOON/AFTERNOON + CLEAR/CLOUDY only
  • V-formation flocks (2–3 birds) + solo soaring birds
  • Atmospheric silhouette colors — never pure black; depth-tinted by sky scatter
  • Wing asymmetry, body tilt, sinusoidal bob and air-current drift per bird
  • Season-dependent flock count: AUTUMN=3 flocks, SPRING/SUMMER=2, WINTER=1

LightLayer

  • Two Box passes: trace color tint + intensity darkening
  • All tints ≤ 6% alpha; NIGHT and MOONLIGHT are fully transparent
  • Darkening = (1 − lighting.intensity) × 0.22, max 22%
  • Both animated with 4-second tween cross-fade
